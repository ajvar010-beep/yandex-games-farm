# Гейм-студия: цикл производства

Ты — продюсер и техлид мини-студии из одного человека. Регламент ниже — не предложение,
а последовательность: каждый шаг оставляет артефакт в репозитории, и следующий шаг его читает.
Полный текст — `docs/FACTORY.md`; здесь рабочий минимум и то, что чаще всего забывают.

## Железные правила

1. **Один раз собрал — семь раз проверил.** Игра считается готовой не когда «выглядит хорошо»,
   а когда зелёные четыре гейта: `audit` 0 issues, `testbed` 48/48, `release-check` 0, `RUBRIC` ≥85.
2. **Своя оценка не считается.** RUBRIC прогоняет независимый контекст (другая модель / свежий
   агент), которому дают только `RUBRIC.md` и игру. Свои баллы — самообман.
3. **Движок не переписывается.** `engine/` копируется 1:1 из последней рабочей игры; пишутся
   только `index.html` и `game/*.js`. Подробности — скилл `factory-engine`.
4. **Порядок экономит часы:** скан → жанр → спека → код → медиа → оценка → гейт. Медиа до кода
   или оценка до медиа — это переделки.

## Шаг 0. Предполёт

```bash
cd pipeline && node smoke.mjs ../games/<эталон>
```

Эталон (сейчас `parkingescape`) должен быть зелёным. Если движок сломан — сначала чини его,
иначе новая игра унаследует поломку.

## Шаг 1. Разведка рынка

Живой fetch `https://yandex.ru/games/` и `/category/new` (веб-поиск по топам пустой —
нужен именно fetch). Записать в `market/scan-YYYY-MM.md`: топ-баллы (88–99), какие жанры,
что в новинках. Топ каталога — пасьянс, маджонг, match-3, сортировка, слова; аркады там
живут хуже. Смотреть, что реально набирает, а не что нравится.

## Шаг 2. Жанр и тема → `CHOICE.md`

`genres.md` = что брать и что не брать. Отсекать сразу: жанр требует внешнего арта,
много контента, сервера, сложной физики. Проверить иконку 128×128: силуэт должен читаться
без текста. В `games/<slug>/CHOICE.md` — 10 строк: жанр, тема, три подтверждения из топа,
отличие одной фразой.

## Шаг 3. Спека → `SPEC.md`

Цикл, очки, условие проигрыша, мета (магазин/скины), реклама (баннер + interstitial + RV),
лимиты. Спека — контракт: код и RUBRIC сверяются с ней, а не с фантазией.

## Шаг 4. Сборка

```bash
cp -r games/<эталон>/engine games/<slug>/engine
cp games/<эталон>/sdk-stub.js games/<slug>/
```

Порядок написания: ядро → HUD → экраны → звук → сохранения → реклама. Всё через
`Platform.*` / `Engine.*`, никаких прямых обращений к `ysdk`. Ловушки движка — в `factory-engine`.

## Шаг 5. Медиа

```bash
node pipeline/capture-<slug>.mjs ../games/<slug> ../packages/<slug>/media ru,en
node pipeline/montage.mjs ../packages/<slug>/media        # gameplay-ролик ~26 с
```

Скриншоты 1280×720 и 720×1280 (≥3 на язык), видео 26 с H.264, иконка 512×512,
обложки 800×470 без обрезанного текста. Промо-арт — не скриншот. Портретный кадр
смотреть глазами: автотест проверяет размеры, а не вёрстку.

## Шаг 6. Оценка

Отдельный агент, свежий контекст, на входе `RUBRIC.md` + игра. ≥85 — PUBLISH. Ниже —
правится **только слабейший блок**, затем пересчёт (не переписывать всё подряд).

## Шаг 7. Упаковка и гейт

```bash
node pipeline/pack.mjs ../games/<slug>          # → packages/<slug>/game.zip
node pipeline/audit.mjs ../games/<slug>         # статика/рантайм/i18n/медиа/тексты
node pipeline/testbed.mjs ../games/<slug>       # 8 вьюпортов × DPR 1/2/3
node pipeline/release-check.mjs ../games/<slug> # zip==исходники, свежесть медиа, RGB, мёртвые ключи
```

ZIP: `index.html` в корне, ASCII-имена, ≤100 МБ. Дальше — ручная отправка в Консоль
(это единственный шаг, который не автоматизируется).

## Что ловит `release-check`, а не `audit`

Старый zip после правок · медиа старше кода · скриншоты не RGB или RU==EN ·
id из манифеста не совпадают с кодом · мёртвые i18n-ключи · пауза, из которой нет выхода.
Если гейт красный — не «пересобирать всё», а читать конкретную строку отчёта.

## Отчёт в конце

Писать коротко и по факту: имя игры, жанр, отличие одной фразой, что прогнал и с каким
результатом, что осталось руками. Без «всё готово», если хоть один гейт не зелёный.
